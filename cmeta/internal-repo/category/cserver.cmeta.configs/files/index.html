JSON

A config artifact is a named settings file of this machine: data.json of config::<name>, in the local repository unless it was made elsewhere. Every command below works the same in cmd, PowerShell and bash; the details of a key give the line for that key.

cx config set <name> --meta.<key>=<value>sets a key (the config is made when it is missing); several --meta. at once are fine
--meta.a.b=va nested key: each dot is one level (test_session.max_keep_mib) - a key whose own name holds a dot cannot be set so
--meta.k,=a,ba list (the comma after the key); a value with commas of its own (a cRef) is one text, with ; between its items when the reader allows it
cx config unset <name> --meta.<key>removes a key - its default applies again
cx config show <name>lists what is set, as --meta. lines to copy, and where its data.json is
cx config read <name>the same for a program: it never makes the config (get does)
A serverreads some configs once, at its start (the cserver: cx app run cserver): restart it after a change; a page reads its keys on every request
A secret(a password, a token, a key) is never shown here; set it on the machine itself - a value typed on the command line stays in the shell's history (cx utils hash_password keeps a password's digest instead)
Your own keysan artifact that reads a config declares its keys in its _desc.yaml (configs: → the config → keys: → each key with desc, type, default, example, secret): they show here with what they do
